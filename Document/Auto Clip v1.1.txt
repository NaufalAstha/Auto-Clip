# AUTO CLIP

## Version 1.1 Feature Specification

**Project Name:** Auto Clip
**Version:** v1.1
**Document Type:** Feature Update / Incremental Development Specification
**Base Version:** Auto Clip v1.0
**Development Approach:** Incremental Feature Addition

---

# 1. Document Purpose

Dokumen ini merupakan spesifikasi pengembangan **Auto Clip v1.1** sebagai lanjutan dari Auto Clip v1.0.

Auto Clip v1.0 telah memiliki pipeline utama:

```text
YouTube URL
     ↓
Gemini Analysis
     ↓
Timestamp
     ↓
yt-dlp
     ↓
Video Clip
```

Pada versi 1.1, pipeline tersebut akan diperluas dengan tiga fitur baru:

1. **Face Tracking / Speaker Detection**
2. **Automatic Vertical Cropping (16:9 → 9:16)**
3. **Automatic Caption / Subtitle**

Pipeline baru:

```text
YouTube URL
     ↓
Gemini Analysis
     ↓
Timestamp
     ↓
yt-dlp
     ↓
Raw Video Clip
     ↓
Face / Speaker Detection
     ↓
Smart Crop 16:9 → 9:16
     ↓
Auto Caption
     ↓
Final Vertical Clip
```

## 6.1 Objective

Video hasil download dari YouTube pada umumnya memiliki format horizontal:

```text

```

```text

       ┌───────────────┐
       │               │
       │               │
```

# 7. Smart Crop Requirement

Cropping **tidak boleh selalu dilakukan dari titik tengah frame**.

Ini merupakan salah satu perubahan utama pada v1.1.

### Incorrect Approach

```text
16:9 Frame

┌─────────────────────────────────────┐
│                                     │
│ PERSON                              │
│                                     │
│                                     │
│                    CENTER           │
└─────────────────────────────────────┘

               ↓

        Center Crop
               ↓

       ┌───────────────┐
       │               │
       │      ❌       │
       │               │
       └───────────────┘
```

Pembicara dapat berada di luar area crop sehingga hasil video tidak memiliki subject utama.

### Required Approach

Crop position harus ditentukan berdasarkan hasil **speaker/face position detection**.

```text
┌─────────────────────────────────────┐
│                                     │
│  PERSON                             │
│                                     │
│                                     │
│                                     │
└─────────────────────────────────────┘
          ↑
          │
      Detection
          │
          ▼

   Crop Center = Person
```

# 8. Feature 2 — Face Tracking / Speaker Position Detection

## 8.1 Definition

Pada v1.1, istilah **Face Tracking** digunakan untuk sistem yang:

> Mendeteksi posisi wajah/pembicara dalam frame video dan menentukan posisi crop berdasarkan lokasi tersebut.

### Important

Sistem **tidak harus mengikuti wajah secara frame-by-frame secara penuh** seperti sistem cinematic face tracking.

Tujuan utama sistem adalah:

> **Menentukan posisi subject yang harus menjadi pusat area crop.**

Dengan kata lain:

```text
Face Tracking
      ↓
Detect Subject Position
      ↓
Determine Crop Position
      ↓
Crop Video
```

Bukan:

```text
Face Tracking
      ↓
Move Camera Continuously
      ↓
Follow Face Every Frame
```

# 11. Multi-Person Detection

Ketika terdapat lebih dari satu wajah dalam frame:

```text
┌─────────────────────────────────────────────┐
│                                             │
│       FACE A              FACE B            │
│                                             │
└─────────────────────────────────────────────┘
```

System harus terlebih dahulu mendeteksi seluruh kandidat wajah.

Output internal dapat berupa:

```python
faces = [

        "y": 180,
        "width": 180,
        "height": 180
    },
    {
        "x": 950,
        "y": 170,
        "width": 190,
        "height": 190
    }

```

Kemudian sistem menentukan strategi crop.

# 12. Crop Decision Logic

Untuk MVP v1.1, sistem harus memiliki prinsip:

### Case A — One Person

Jika hanya terdapat satu wajah:

```text
1 Face
 ↓
Use Face Position
 ↓
Set Crop Center
```

---

### Case B — Multiple People

Jika terdapat beberapa wajah:

```text
Multiple Faces
      ↓
Determine Subject Layout
      ↓
Determine Best Crop Position
```

Jika beberapa orang masih dapat masuk dalam satu frame vertical:

```text
      HOST
       +
     GUEST

        ↓

   ┌───────────┐
   │           │
   │ HOST      │
   │           │
   │ GUEST     │
   │           │
   └───────────┘
```

Jika tidak memungkinkan memasukkan seluruh subject:

```text
Multiple Faces
      ↓
Prioritize Active Speaker
      ↓
Crop Toward Active Speaker
```

---

# 13. Active Speaker Detection

Untuk meningkatkan kualitas crop pada podcast, sistem dapat menggunakan informasi audio/speech sebagai signal tambahan.

Konsep:

```text
Face Detection
      +
Speech Activity
      ↓
Active Speaker Candidate
      ↓
Crop Position
```

Namun fitur **active speaker recognition yang kompleks bukan mandatory untuk MVP v1.1**.

Prioritas implementasi:

```text
Priority 1:
Face Position Detection

Priority 2:
Multi-face Handling

Priority 3:
Audio/Speech-based Active Speaker Detection
```

Jika active speaker detection belum stabil, sistem harus tetap dapat bekerja menggunakan face detection.

---

# 14. Crop Position Smoothing

Perubahan posisi crop tidak boleh terlalu agresif.

Contoh buruk:

```text
Frame 1 → LEFT
Frame 2 → CENTER
Frame 3 → RIGHT
Frame 4 → LEFT
Frame 5 → CENTER
```

Hasil:

```text
❌ Video terasa bergoyang / berpindah secara kasar
```

Sistem harus menggunakan smoothing terhadap posisi crop.

Contoh:

```text
Detected Position
       ↓
Position Smoothing
       ↓
Crop Position
```

Tujuan:

> Menghasilkan perpindahan framing yang natural dan tidak mengganggu penonton.

---

# 15. Crop Transition

Jika subject berpindah posisi secara signifikan:

```text
LEFT
 ↓
CENTER
 ↓
RIGHT
```

Crop position dapat berpindah secara bertahap.

Contoh:

```text
Frame 1
Crop X = 200

Frame 10
Crop X = 350

Frame 20
Crop X = 500
```

Bukan:

```text
Frame 1
Crop X = 200

Frame 2
Crop X = 500
```

Tujuannya adalah menghindari efek "teleporting crop".

# 17. Feature 3 — Auto Caption

## 17.1 Objective

Auto Clip v1.1 harus mampu menghasilkan subtitle secara otomatis dari audio video.

Flow:

```text
Video Clip
    │
    ▼
Speech Recognition
    │
    ▼
Transcript
    │
    ▼
Timestamped Words / Sentences
    │
    ▼
Subtitle Generation
    │
    ▼
Burn Caption Into Video
```

---

# 18. Caption Requirements

Caption harus:

* berasal dari ucapan dalam video;
* memiliki timing yang sesuai dengan audio;
* muncul ketika pembicara berbicara;
* menghilang ketika bagian speech selesai;
* dapat dibaca pada video vertical;
* tidak keluar dari area aman video.

Contoh:

```text
┌─────────────────┐
│                 │
│                 │
│    PERSON       │
│                 │
│                 │
│ "This is        │
│  very important"│
└─────────────────┘
```

---

# 19. Caption Timing

Caption harus memiliki timestamp.

Contoh internal data:

```json
{
  "segments": [
    {
      "start": 0.50,
      "end": 2.80,
      "text": "This is very important"
    },
    {
      "start": 3.10,
      "end": 5.20,
      "text": "because it changes everything"
    }
  ]
}
```

Dengan demikian subtitle tidak hanya berupa teks statis.

---

# 20. Caption Style

MVP v1.1 tidak membutuhkan sistem caption design yang sangat kompleks.

Minimum requirement:

* readable;
* high contrast;
* berada pada safe area;
* ukuran font cukup besar untuk mobile;
* tidak menutupi wajah pembicara jika memungkinkan.

Recommended default position:

```text
┌───────────────┐
│               │
│    PERSON     │
│               │
│               │
│  CAPTION      │
│  CAPTION      │
└───────────────┘
```

Caption harus ditempatkan dengan mempertimbangkan posisi wajah.

Jika wajah berada di bagian bawah:

```text
Face
 ↓
Move Caption
 ↓
Avoid Face
```

---

# 21. Caption Highlight

Caption dapat menggunakan perubahan visual sederhana untuk meningkatkan perhatian.

Contoh:

```text
I THINK THIS IS
      IMPORTANT
```

Kata yang sedang diucapkan dapat diberikan emphasis/highlight.

Namun fitur word-level highlighting hanya menjadi **enhancement**.

Requirement minimum:

> Caption harus muncul dan berubah mengikuti speech.

---

# 22. Recommended Caption Processing

Speech-to-text engine harus menghasilkan:

```text
Audio
 ↓
Transcript
 ↓
Timestamp
 ↓
Subtitle
```

Jika engine mendukung word-level timestamp:

```text
Word
+
Start Time
+
End Time
```

maka dapat digunakan untuk menghasilkan caption yang lebih dinamis.

Namun pipeline v1.1 tetap harus dapat bekerja dengan segment-level timestamp.

```text
        ↓
```

# 31. Face Detection Failure Handling

Face detection tidak selalu berhasil.

Kemungkinan:

* wajah tertutup;
* wajah terlalu kecil;
* pencahayaan buruk;
* kamera berubah;
* frame kosong;
* scene tidak memiliki manusia.

Jika face detection gagal:

```text
Face Detection Failed
        ↓
Fallback Crop
        ↓
Center Crop
```

Fallback wajib tersedia.

Jadi:

```text
Face Detection
      │
      ├── Success → Smart Crop
      │
      └── Failed  → Center Crop
```

Sistem tidak boleh crash hanya karena tidak menemukan wajah.

---

# 32. Multiple Face Failure Handling

Jika terdapat banyak wajah tetapi sistem tidak dapat menentukan active speaker:

```text
Multiple Faces
      ↓
Unable to determine active speaker
      ↓
Calculate suitable shared crop
      ↓
If impossible:
Use stable/default crop strategy
```

Tujuan utama:

> Tetap menghasilkan video yang usable daripada gagal total.

---

# 33. Caption Failure Handling

Jika speech-to-text gagal:

```text
STT Failed
   ↓
Log Error
   ↓
Generate Video Without Caption
```

Caption failure **tidak boleh membuat seluruh proses video gagal**, kecuali requirement bisnis berikutnya menentukan caption sebagai mandatory.

Untuk MVP v1.1:

> Video tanpa caption lebih baik daripada pipeline gagal total.

# 38. Performance Consideration

Face detection dan speech recognition dapat menjadi processing yang cukup berat.

Pipeline harus menghindari proses yang tidak diperlukan.

Contoh:

```text
BAD:

Detect face
on every unnecessary frame
at maximum resolution
```

Lebih baik menggunakan strategi sampling frame yang cukup untuk menentukan perubahan posisi subject.

Namun kualitas tracking harus tetap menjadi prioritas.

Optimasi dilakukan setelah baseline implementation berhasil.

---

# 39. Important Design Principle — Detection vs Tracking

Tim produksi harus membedakan dua konsep:

### Detection

Menjawab:

> "Di mana pembicara berada?"

### Tracking

Menjawab:

> "Bagaimana posisi pembicara berubah sepanjang video?"

Auto Clip v1.1 membutuhkan keduanya dalam bentuk sederhana:

```text
Frame
 ↓
Detect Face
 ↓
Get Position
 ↓
Compare With Previous Position
 ↓
Smooth Position
 ↓
Generate Crop Path
```

Tidak diperlukan sistem facial recognition untuk mengetahui **siapa** orang tersebut.

Sistem hanya perlu mengetahui:

> **di mana subject berada.**

---

# 40. No Facial Identity Recognition Required

Auto Clip v1.1 **tidak membutuhkan facial recognition / identity recognition**.

Sistem tidak perlu mengetahui:

```text
"Ini adalah John."
```

Sistem hanya perlu mengetahui:

```text
"Di frame ini terdapat wajah pada koordinat X,Y."
```

Ini membuat requirement lebih sederhana dan sesuai tujuan product.
